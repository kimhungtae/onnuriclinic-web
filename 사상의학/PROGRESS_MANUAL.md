## 2. 작업 두 축의 정의

### 2.1 왜 두 축인가
- **임상 모듈 라인 (A~E)**: 진료실에서 무엇을 하는가 — 자가설문·시진·기능검사·처방 추천. 한의학 전문가 의견·임상 자료에 깊게 의존.
- **플랫폼·인프라 라인 (P/T)**: 그 모듈들이 어떤 코드·DB·인증·실시간 위에서 돌아가는가 — Next.js·Turso·매니저 큐·IP 제한.

두 라인은 **독립적으로 진행되어 한 지점에서 만남**. 임상 모듈은 단일 HTML로도 동작 가능하지만, 진료실 워크플로(키오스크↔카운터↔원장실 실시간 동기화)는 플랫폼 라인 없이 불가능.

### 2.2 두 라인의 매핑

| 임상 모듈 | 연결된 플랫폼 작업 (T) | 통합 시점 |
|---|---|---|
| A. 자가설문 (v24.html) | T3·T4·T5 (설문 ETL·UI·채점 API) | Phase 1 |
| B. 의사결정나무 | T2 (스키마: syndromes/contradictions) | Phase 2 |
| C. 정밀 시진 | T7.5 (매니저 라이브 큐 내 세션 상세) | Phase 1~2 |
| D. 기능 검사 | T10 (환자 이력·진료 메모) | Phase 2 |
| E. 처방 추천 | T8·T9 (처방 ETL·검색 페이지) | Phase 2 |
| (전체) | T7 (인증·RBAC), T12 (네트워크 제어) | Phase 1 후반 |
