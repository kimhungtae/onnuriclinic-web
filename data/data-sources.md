## 2. `prescriptions_curated.json` — 큐레이션 처방 (매칭 엔진용) · ★원장 검수 대상★

> **2026-05-22 류주열식 중심 재구성**: 원장이 실제 진료에서 **류주열식 사상처방을 주로 쓰고 고전 사상의학 처방을 참조로** 적용한다고 확인됨. 이에 큐레이션을 **류주열 처방 기준**으로 재정렬 — 각 처방에 `ryuCode`(류주열 처방 코드)를 지정하고 `composition`(구성)을 류주열 사상처방개정판에서 채웠다. 고전 처방은 `classicRef`(참조 메모)로만 둔다.

**스키마**
- `ryuCode` — 류주열 처방 코드(H/P###). `null`이면 류주열 책 미수록(고전 처방).
- `composition` — 류주열 구성(약재). 6개는 류주열 DB에서 채워짐, 2개(갈근조위탕·형방패독산)는 류주열 미수록이라 `null`.
- `ryuAltCodes` — 류주열 책의 다른 관련 처방(다른 버전·유사 처방). 모듈 E 카드에 "류주열 다른 버전"으로 구성 비교 표시.
- `classicRef` — 고전 사상의학 처방 참조 메모.
- `verified:false` — 한열·주증 등 아직 원장 미검수. 모듈 E 화면에 "원장 검수 전" 배지.

### 류주열 처방명 ≠ 고전 처방명 (유의)
이름이 같아도 구성이 다를 수 있다 — 예: 류주열 P013 형방지황탕 구성에는 지황(地黃)이 없다(고전 형방지황탕은 숙지황 포함). 류주열에 H019 태음조위탕 + H020 류씨태음조위탕이 별도 존재. '갈근조위탕'·'형방패독산'은 류주열 책에 동명이 없다(형방패독산은 류주열 P001 '이씨형백패독산'이 유사 후보). 이런 차이는 각 처방의 `classicRef`·`ryuAltCodes`에 명시.

### ▶ 원장님 검수 요청
- [ ] 각 처방 **한열·음양형** 확인 (현재 cowork_spec 초안값)
- [ ] **주증(symptoms)** 검수 — 현재 Claude 초안값(표준 처방 적응증 기반, `symptom_chips.json` 칩 문구). 매칭 정확도 직결
- [ ] **갈근조위탕·형방패독산** — 실제 쓰시는 류주열 처방으로 연결(`ryuCode` 지정) 또는 큐레이션에서 제외
- [ ] **태음조위탕** — H019 / H020(류씨태음조위탕) 중 실제 쓰시는 것 확정
- [ ] **주의·부적합 시그널·가감** 보강
- [ ] 완료한 처방은 `verified:true`로 — 화면 "검수 전" 배지 사라짐
- 입력 방식: `prescriptions_curated.json` 직접 편집, 또는 Claude Code에 불러주면 반영. 갱신 후 모듈 E HTML의 `RX_CURATED` 재임베드 필요.

## 4. 미해결·주의

- 류주열 XLSX는 **처방명·구성만** 제공 — 한열·음양형·주증·가감은 별도 임상 자료(안준철 강의록 HWP/PDF, 사상임상의학회 정리)에서 와야 하나 구조화가 어려움. 그래서 본 작업은 **검증 가능한 8개 큐레이션 + 342개 검색 참조** MVP 구조를 택함.
- 큐레이션 메타데이터를 추측으로 채우지 않음 — `null`은 "원장 확인 필요"를 의미하며 모듈 E 화면에서 그렇게 표시됨.
- 자료 권리: 류주열·안준철·하만종·권재식 자료는 원내 한정 사용. 공개 전 협의 필요 (PHASE1A §7).

## 5. `byeonjeung_map.json` · `prescriptions_meta.json` — 변증 기반 전체 처방 (2026-05-22 신규)

> **목적**: 큐레이션 8처방 한계를 넘어, 류주열 처방 전체에 한열·변증·증상을 매핑. 모듈 E에 **변증 기반 처방 조회** 패널 추가.

### 출처
- `D:\사상의학\2사상의학\새로사상\새로사상책_외감,내상변증편(n처방번호기재).pdf` — 170개 변증(證)마다 증상([괄호])과 체질별·한열별 류주열 처방코드.
- `D:\사상의학\2사상의학\새로사상\새로사상책_한자ㆍ열자와_내상잡병_변증.pdf` — 변증의 한자(寒)/열자(熱) 분류표.

### 파이프라인
1. `byeonjeung_map.json` — 외감·내상변증편 PDF를 **그대로 전사**. 170개 변증 항목. 각 항목: `cat`(분류)·`jeung`(변증 한자)·`sx`(증상 한자 배열)·`rx`(체질 te/sy/ty/se별 hot/cold/any 처방코드). 가감 메모는 제외하고 처방코드만 전사.
2. `build_meta.js` 실행 → `prescriptions_meta.json` 생성. byeonjeung_map 역인덱싱 + prescriptions_full 조인. 처방별 `hanyul`(열로만 등장→hot/한으로만→cold/양쪽→mixed/단일만→unknown)·`byeonjeung`·`symptoms`.
3. `embed_byeonjeung.js` 실행 → 모듈 E HTML의 `BYEONJEUNG` 상수에 임베드(자료 변경 시 자리표시자 복원 후 재실행).

### 빌드 결과 (2026-05-22)
- 변증 170개 · 메타 생성 처방 **287 / 류주열 342개** (나머지 55개는 변증서 미수록 → 검색참조용 잔류).
- 한열: 열 67 · 한 67 · 혼합 8 · 미상 145. (미상=단일 처방으로만 등장 — 한열이 변증 자체에 귀속되며 모듈 E는 변증별 hot/cold/any 역할을 직접 사용.)

### ★ 원장 검수 / 발견 사항 ★
- [ ] **형방패독산 = 류주열 P001 (이씨형백패독산)** 확정 — 책에서 風寒束肺 등의 **열(熱)** 처방으로 분류됨. 큐레이션 초안(`hyeongbang_paedok` = 한)과 차이. `prescriptions_curated.json`의 `ryuCode` 연결 + 한열 재확인 필요.
- [ ] **지황백호탕 P009** — 膀胱蓄血證에서 열·한 양쪽 옵션으로 등장 → meta 한열 `mixed`. 큐레이션은 열. 원장 확인.
- [ ] **태음조위탕 H019** — 한(寒)으로 일관 등장(변증 20개), 큐레이션과 일치.
- [ ] 변증서 전사값(증상·처방코드)은 OCR 기반 — 원장 표본 검수 권장.
- 자료 권리: §4와 동일 — 원내 한정.
